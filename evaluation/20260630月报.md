工作主要内容

	围绕 LMCache 单卡链路，统一整理了原生 vLLM baseline、LMCache SSD-only baseline、LMCache + BaM shadow 与 prefer-load 等脚本入口，并同步整理了 evaluation 目录下的 README、结果文档和日志组织方式，形成了可复用的实验框架。
2、LMCache KV chunk 到 BaM 128KB page 布局重构。
	针对 LMCache KV chunk 在 BaM 上的存储组织，完成了从早期 1KB token-row/page 到固定 128KB page 布局的迁移，补充了 chunk 到 page 的映射方式、layout 说明以及对应的读写验证和测试代码。
3、LMCache + BaM shadow write 与 prefer-load 闭环打通。
	在写路径上完成了 LMCache chunk 写入 BaM 的实现；在读路径上完成了 prefer-load 接入，使共享前缀场景下可以优先从 BaM 读回 KV chunk，再交回 LMCache / vLLM 继续执行，同时补充了对应的正确性校验代码。
4、KV cache 专用 fast path 建设。
	围绕 KV cache 读取需求，新增了独立的 KV fast path，代码上推进了 chunk metadata 组织、page request 生成、batch read、GPU refill 与 batch consume 等模块，并补充了 replay、batch replay、trace replay 等验证脚本。
5、GPU worker / rowctx executor 抽象与轮询主线收敛。
	在 BaM_IOStack 与上层适配中，完成了 rowctx 与 gpu_worker 两套 executor 组织，并围绕 submit、poll、ready、consume 等环节逐步收敛当前 KV 路径的轮询主线；同时对实验过程中废弃的过渡性轮询代码做了归档和清理。
6、真实 vLLM + LMCache 路径接入与 direct retrieve 推进。
	将 KV fast path 接入到真实 LMCache connector / storage manager 调用链中，支持在 prefetch / get 阶段收集待恢复 chunk、执行 batch read，并将结果回填到 LMCache memory object 或上层 KV cache，完成了 direct retrieve 主线的代码接通。
7、Direct placement 原型与性能定位。
	在已有 KV fast path 基础上，继续推进 direct placement，代码上实现了基于 plan 的批量组织、merged refill 与一次性 transfer 等原型路径，并围绕 placement / refill 相关模块持续开展整理和后续优化准备。
