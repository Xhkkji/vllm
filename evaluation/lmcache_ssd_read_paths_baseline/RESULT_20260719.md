# LMCache SSD Read Path Baseline 20260719

## 测试目的

这组测试用于和当前 BaM one-copy 稳定基线做通路 baseline 对比，重点观察 LMCache 从 SSD 读回 KV chunk 时的两条路径：

- `ssd_cpu_gpu`：原生 LMCache V0 local_disk，数据路径是 `SSD -> CPU MemoryObj -> multi_layer_kv_transfer -> vLLM paged KV cache`。
- `gds_gpu`：LMCache-style GDS wrapper，数据路径是 `SSD/cufile -> CUDA chunk tensor -> LMCache MemoryObj -> multi_layer_kv_transfer -> vLLM paged KV cache`。
- `bam one-copy`：当前稳定基线，数据路径是 `BaM cache -> vLLM paged KV cache`，由 persistent service + mover CTA 完成一次写入。

这三条链路使用同一个 Qwen2.5-7B-Instruct 单卡样例，request 2 复用 request 1 的 prompt，用于触发前缀 KV 读回。

## 本轮最新输出确认

本轮检查的最新输出没有发现路径报错、CUDA illegal access 或文本乱码。三条链路都生成了相同语义的 Qwen2.5-7B-Instruct 介绍文本，因此当前 baseline 对比可以先按“输出正常”处理。

request 2 是本轮更有意义的读回对比点：

| 对比项 | request 2 端到端 | 相对 BaM one-copy 差距 |
| --- | ---: | ---: |
| 原生 LMCache SSD vs BaM one-copy | 2.0372s vs 1.5252s | 慢 0.5120s，约 1.34x |
| LMCache-style GDS vs BaM one-copy | 2.0507s vs 1.5252s | 慢 0.5255s，约 1.34x |

这说明当前 BaM one-copy 链路相对两条 LMCache SSD 路径都有稳定优势。GDS wrapper 的 4 个 chunk 纯读合计约 `39.97ms`，BaM one-copy 的 read/direct placement 为 `19.926ms`，纯读路径大约快 `2.0x`；但端到端差距超过 `0.5s`，明显大于底层读差异。因此下一步如果继续对比，需要把 LMCache 原生路径里的 retrieve、MemoryObj 构造、`multi_layer_kv_transfer` 和 xFormers 前缀消费分别打点，否则很难判断 2.04s 中真正重的是哪一段。

## 结论

当前这组结果说明，BaM one-copy 仍明显快于 LMCache 原生 SSD 和 LMCache-style GDS wrapper：

- 相比原生 LMCache SSD，BaM one-copy request 2 快约 `0.512s`，约 `1.34x`。
- 相比 GDS wrapper，BaM one-copy request 2 快约 `0.525s`，约 `1.34x`。
- GDS wrapper 的底层 chunk read 合计约 `40ms`，而 BaM one-copy 的 read/direct placement 合计约 `20ms`，但端到端差距大于 20ms，说明 LMCache 原生 retrieve/rebuild、MemoryObj 包装、`multi_layer_kv_transfer`、xFormers 前缀消费等上层固定开销仍然占主要部分。

需要注意，`gds_gpu` 的 request 1 包含 GDS 初始化和 shadow write，第一条 chunk 写入耗时 `577.865ms`，这是首次初始化/打开路径的冷启动成本，不应直接作为稳态读性能判断。request 2 才是本轮更有意义的读回对比点。

## 后续建议

后续如果继续做通路 baseline，应补两类更细粒度统计：

- 在原生 LMCache SSD 路径里增加 chunk 级 `LocalDiskBackend.get_blocking()` 和 `multi_layer_kv_transfer(direction=false)` 计时，否则只能看到端到端。
- 在 GDS wrapper 路径里拆开 `GDS read`、`populate MemoryObj`、`multi_layer_kv_transfer` 三段，判断当前 2.05s 中到底是存储读慢，还是 LMCache/vLLM 注入路径慢。
